# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Appointment-booking web app (Calendly-like), Hexlet learning project. Currently only the technical skeleton exists (one `GET /api/health` endpoint); no business logic yet.

## Do not touch

- `.github/workflows/hexlet-check.yml` is auto-generated by Hexlet: never edit, delete or rename it (nor the repo). Own CI lives in `.github/workflows/ci.yml`.

## Architecture: contract-first pipeline

```
api/main.tsp (TypeSpec) --tsp compile--> api/openapi/openapi.yaml (OpenAPI 3.0.0, committed)
                                              |--> frontend/src/api/generated/ (hey-api SDK, gitignored)
backend/ (Ktor) implements the contract by hand (no server codegen)
```

- The API contract is the source of truth: change `api/main.tsp`, rebuild, then regenerate the SDK. CI fails (`git diff --exit-code -- api/openapi`) if the committed `openapi.yaml` is stale, so commit it together with `.tsp` changes.
- `frontend/src/api/generated/` must never be edited or committed; it is regenerated by `sdk:generate` and excluded from ESLint. Any frontend task needing the SDK depends on `sdk:generate` in `mise.toml`.
- Backend routes are not generated from OpenAPI, so keep `backend/src/main/kotlin/calendar/Application.kt` routes/DTOs manually in sync with the `.tsp`. All routes live under `/api`; Vite dev server proxies `/api` to `localhost:8080`, and the SDK is generated with a relative base URL (`baseUrl: false` in `frontend/openapi-ts.config.ts`).
- Operation names in TypeSpec become SDK function names (`op getHealth` -> `getHealth()`). `@operationId` is not available without adding `@typespec/openapi`.

## Commands

Everything is driven by mise (Java `temurin-21`, Node `24`); CI runs the same command.

```
mise run check            # full pipeline: api format, SDK gen, frontend typecheck/lint/test/build, backend ktlint/test/assemble
mise run dev:backend      # Ktor on :8080
mise run dev:frontend     # Vite on :5173
mise tasks                # list all tasks
```

Single tests / direct tools (run inside the subproject):

```
cd backend  && ./gradlew test --tests "calendar.HealthTest"      # Windows: gradlew.bat
cd backend  && ./gradlew ktlintFormat                            # auto-fix ktlint
cd frontend && npx vitest run src/App.test.tsx -t "shows backend status"
cd api      && npm run build                                     # regenerate openapi.yaml
cd frontend && npm run generate:sdk                              # needs api/openapi/openapi.yaml
```

mise Gradle tasks call `java -classpath gradle/wrapper/gradle-wrapper.jar org.gradle.wrapper.GradleWrapperMain` instead of `./gradlew` so they work in PowerShell, cmd and POSIX shells alike.

## Version constraints

- All dependency versions are pinned exactly (no `^`/`~`). Backend versions live in `backend/gradle/libs.versions.toml`.
- TypeScript must stay on 6.0.x: typescript-eslint 8.x supports `<6.1.0` only, although npm `latest` is 7.x.
- TypeSpec packages (`compiler`, `http`, `openapi3`) must share the same version. Emitter target is OpenAPI 3.0.0 (`api/tspconfig.yaml`).
- Version catalog keys: avoid names where one key is a prefix of another with a dash (e.g. `ktlint` and `ktlint-plugin`) since `libs.versions.ktlint` then becomes a group, not a value.
- `@hey-api/openapi-ts` is 0.x with frequent breaking changes: bump deliberately and re-check generated output.

## Environment notes (corporate network)

- Developer machine is behind an authenticated HTTP proxy with corporate TLS certs and an internal Nexus mirror. Never disable SSL verification. Keep corporate URLs and credentials out of the repo: committed files must reference only public sources (`mavenCentral()`, `registry.npmjs.org` in lock files, `services.gradle.org` in the wrapper). Local mirror/proxy/truststore settings belong in `~/.gradle` and `~/.npmrc` (see README).
- After `npm install`, rewrite any mirror host in `package-lock.json` `resolved` URLs back to `https://registry.npmjs.org/` before committing. Use `npm ci --ignore-scripts` for installs.
- Files use LF (`.gitattributes`, `.editorconfig`); ktlint enforces `.editorconfig`, so CRLF breaks `ktlintCheck`.
