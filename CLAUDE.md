# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Appointment-booking web app (Calendly-like), Hexlet learning project. Endpoints so far: `GET /api/health`, `GET /api/owner`, `GET /api/meeting-types`, `GET /api/meeting-types/{id}`, `POST /api/meeting-types`, `GET /api/meeting-types/{id}/slots`, `POST /api/bookings`, `GET /api/bookings` (upcoming bookings of all meeting types: `startAt` strictly after `clock.instant()`, ascending, no pagination).

## Do not touch

- `.github/workflows/hexlet-check.yml` is auto-generated by Hexlet: never edit, delete or rename it (nor the repo). Own CI lives in `.github/workflows/ci.yml`.

## Architecture: contract-first pipeline

```
api/*.tsp (TypeSpec: main, owner, meeting-types, errors) --tsp compile--> api/openapi/openapi.yaml (OpenAPI 3.0.0, committed)
                                              |--> frontend/src/api/generated/ (hey-api SDK, gitignored)
backend/ (Ktor) implements the contract by hand (no server codegen)
```

- The API contract is the source of truth: change the `api/*.tsp` files, rebuild, then regenerate the SDK. CI fails (`git diff --exit-code -- api/openapi`) if the committed `openapi.yaml` is stale, so commit it together with `.tsp` changes.
- `frontend/src/api/generated/` must never be edited or committed; it is regenerated by `sdk:generate` and excluded from ESLint. Any frontend task needing the SDK depends on `sdk:generate` in `mise.toml`.
- Backend routes are not generated from OpenAPI, so keep `backend/src/main/kotlin/calendar/Application.kt` routes/DTOs manually in sync with the `.tsp`. All routes live under `/api`; Vite dev server proxies `/api` to `localhost:8080`, and the SDK is generated with a relative base URL (`baseUrl: false` in `frontend/openapi-ts.config.ts`).
- Backend config comes from env vars (`AppConfig.fromEnvironment`, passed into `Application.module(config)`): `OWNER_NAME`, `OWNER_BIO`, `OWNER_TIME_ZONE` (IANA id, validated at startup), with defaults. Unhandled exceptions become 500 `ApiError {code: INTERNAL_ERROR}` via StatusPages. Meeting types live in memory behind `MeetingTypeRepository` (`Application.module(config, meetingTypes)`; the default is seeded with 15 and 30 minute types, lost on restart); an unknown or malformed id gives 404 `MEETING_TYPE_NOT_FOUND`. Kotlin `allWarningsAsErrors` is on.
- Slots (`GET /api/meeting-types/{id}/slots`) come from `SlotCalculator.calculate(clock, schedule, durationMinutes, busy)`, a pure function: tests inject a fixed `java.time.Clock` and booking intervals (`TimeRange` via `BusyTimeSource`; in the app the bookings repository is the busy source). The Schedule (`Schedule.kt`) is config: local intervals + IANA zone. DST rules (gap: no slot, overlap: first occurrence) are explicit in the calculator; see ADR 0001. Frontend component tests run with `TZ=Asia/Tbilisi` set in `frontend/vite.config.ts`.
- Request validation lives in one module, `backend/src/main/kotlin/calendar/Validation.kt` (`Limits` constants, `validateMeetingTypeInput`, `trimmedLength`); add new rules there, never inline in routes. Text is trimmed, then measured in Unicode code points. Bodies are parsed strictly by hand (`Json.parseToJsonElement`): broken JSON gives 400 `MALFORMED_REQUEST`, unknown fields/wrong types/bounds give 400 `VALIDATION_ERROR` with `fieldErrors`. The TypeSpec `minLength`/`maxLength` count UTF-16 units in OpenAPI tools, so they only document the bounds; the backend is authoritative.
- Backend API tests check every response against the contract with one shared helper: call `response.assertMatchesContract()` (`backend/src/test/kotlin/calendar/ContractValidator.kt`, `openapi-request-validator-core`, test-only) on each `testApplication` response, including 404/500 `ApiError` ones; do not hand-write schema checks. For POSTs pass the request body (`assertMatchesContract(body)`) so the request is validated too, or `validateRequest = false` for requests that are invalid on purpose. The helper validates status, `Content-Type`, body schema and formats (`uuid`) and rejects undeclared fields, statuses and paths. `build.gradle.kts` passes `api/openapi/openapi.yaml` to tests as the `openapi.spec` system property and a task input, so tests re-run when the contract changes. Not caught: constraints that are not in the schema (e.g. a path `id` without `format: uuid`, IANA time zones, multiples of 15 minutes).
- Operation names in TypeSpec become SDK function names (`op getHealth` -> `getHealth()`). `@operationId` is not available without adding `@typespec/openapi`.

### Booking creation (backend)

`POST /api/bookings` -> `BookingService.create` (`BookingService.kt`). Order of checks 400 -> 404 -> 422 -> 409; 422 `INVALID_SLOT` = not offered by `SlotCalculator` even with no bookings, 409 `SLOT_TAKEN` = offered but overlapping any booking. Availability re-check and insert run in ONE critical section: `BookingRepository.inCriticalSection` (`InMemoryBookingRepository`, a single `ReentrantLock` that also guards `busyRanges()`/`list()`); the Clock is read inside it. Never add a check-then-insert outside it. Guest name/email rules live in `Validation.kt`. Known limitation: no idempotency keys, a lost 201 is invisible to the client and a retry gets 409 (see `docs/domain-rules.md`).

## Frontend pages

Routes via `react-router` (`BrowserRouter` in `main.tsx`): `/owner` (`OwnerPage`: permanent no-auth warning, block "Предстоящие встречи" on top (`UpcomingBookings`: `GET /api/bookings` + `GET /api/owner`, times formatted via Intl in `Owner.timeZone` with a label, "Обновить" button disabled while loading, no polling; titles joined by `meetingTypeId` from the already-loaded types), meeting-type list, create form with field errors from `fieldErrors`; public, deliberately NOT linked from the home page), `/` (`HomePage`, meeting-type cards) and `/book/:meetingTypeId` (`BookingPage`: slot picker, then name/email form (`BookingForm`), then `BookingConfirmation` on the same screen; on 409/422 the slots reload and typed name/email stay; the meeting type comes from `GET /api/meeting-types/{id}`, a 404 shows "Тип встречи не найден" with a link home). The owner block (`GET /api/owner`) and the cards (`GET /api/meeting-types`) are loaded via the generated SDK with loading/error/success states (`useApiResource`; tests stub fetch with `src/testApi.ts`). There is no static meeting-type data in the frontend. Never hand-write TS copies of API DTOs: import them from `./api/generated`. Domain terms: `GLOSSARY.md`; not-yet-implemented business rules: `docs/domain-rules.md`.

## Commands

Everything is driven by mise (Java `temurin-21.0.13+9.0.LTS`, Node `24.22.2`, pinned exactly in `mise.toml`; CI pins mise `2026.10.25` and has two independent jobs: `check` = `mise run check:fast`, `e2e` = `mise run e2e` with the report uploaded as an artifact). Install: `winget install jdx.mise` (PowerShell) then `mise trust && mise install`. Commands are identical in PowerShell and bash. For Gradle with a local mirror/cache set `GRADLE_USER_HOME` in your own environment, never in committed files.

```
mise run check:fast       # everything except E2E: api format, api drift, SDK gen, frontend typecheck/lint (--max-warnings 0)/test/build, backend ktlint/test/assemble
mise run check            # full set: check:fast + e2e
mise run e2e:install      # download Playwright's Chromium (needs HTTPS_PROXY + https_proxy and NODE_USE_SYSTEM_CA=1 behind the corporate proxy, see README)
mise run e2e              # browser E2E (package e2e/): real Ktor in test mode + Vite + Playwright
mise run e2e:typecheck    # tsc for e2e/ (part of check:fast; e2e has no ESLint)
mise run api:drift        # fresh contract build in api/.tmp/openapi (gitignored) must equal committed api/openapi/openapi.yaml byte-for-byte
mise run api:update       # regenerate and overwrite the committed api/openapi/openapi.yaml (commit it with the .tsp change)
mise run dev:backend      # Ktor on :8080
mise run dev:frontend     # Vite on :5173
mise tasks                # list all tasks
```

Single tests / direct tools (run inside the subproject):

```
cd backend  && ./gradlew test --tests "calendar.HealthTest"      # Windows: gradlew.bat
cd backend  && ./gradlew ktlintFormat                            # auto-fix ktlint
cd frontend && npx vitest run src/App.test.tsx -t "home page lists meeting types"
cd api      && npm run build                                     # regenerate committed openapi.yaml (= mise run api:update)
cd frontend && npm run generate:sdk                              # needs api/openapi/openapi.yaml
```

mise Gradle tasks call `java -classpath gradle/wrapper/gradle-wrapper.jar org.gradle.wrapper.GradleWrapperMain` instead of `./gradlew` so they work in PowerShell, cmd and POSIX shells alike. Task graph: `api:build` (fresh scratch dir) -> `api:drift` -> `sdk:generate` -> frontend tasks; `backend:check` (one Gradle run of ktlintCheck test assemble) depends on `api:drift`. Do not run `backend:lint/test/build` in parallel: they share `backend/build` and race (observed with three parallel Gradle runs).

## Browser E2E (`e2e/`)

- Separate npm package `calendar-e2e` (`@playwright/test` 1.64.1, TypeScript 6.0.3); `mise run install` runs `npm ci --ignore-scripts` for it; frontend Vitest/tsc/ESLint never see it. `e2e/playwright.config.ts` starts the real backend (`gradle run`, cwd `backend`, readiness `GET /api/health`) and Vite (`--port 5173 --strictPort`); `reuseExistingServer` is false only when `CI` is set. One worker, retries 0 locally / 1 in CI, guest time zone `Asia/Tbilisi`, locale `ru-RU`. `PW_CHANNEL=msedge|chrome` optionally swaps in an installed browser (CI uses bundled Chromium).
- Backend test mode is enabled ONLY by `CALENDAR_TEST_MODE=true` (`AppConfig.testMode`): requires `CALENDAR_FIXED_NOW` (ISO-8601 instant, fixed `Clock`), registers `POST /__test__/reset` (204; clears Bookings, restores the two seeded Meeting types with new ids and the initial clock) and `POST /__test__/clock` (body `{"now": "<ISO-8601 UTC instant>"}`; 204, 400 on invalid input; moves the clock, `AdjustableClock`), binds `127.0.0.1`. Without test mode the routes are a 404 and `CALENDAR_FIXED_NOW` makes startup fail. The routes are not in the TypeSpec/OpenAPI contract. Never enable test mode outside the E2E job or a local E2E run.
- Tests import `test`/`expect` from `e2e/tests/fixtures.ts`: an auto fixture calls the reset route directly on `http://127.0.0.1:8080` before every test (Vite proxies only `/api`), so tests must not depend on order.
- Specs: `home.spec.ts` (smoke) and `guest.spec.ts` (booking with confirmation in the guest zone and return home; two Guests in two isolated browser contexts booking the same Slot -> 409 message, refreshed slot list, typed name/email kept; form validation errors at the fields; unknown meeting type and unknown path). Expected clock times are hand-written literals: frozen now = Mon 2 Nov 2026 11:00 Almaty = 10:00 Tbilisi, so today's first Slot is 10:15 and Tue 3 Nov starts at 08:00 in the guest zone. Extra browser contexts via `browser.newContext(...)` do not inherit the config `use` options: pass `baseURL`, `timezoneId`, `locale` explicitly.
- `owner.spec.ts`: `/owner` warning and no link to it on the home page; creating a Meeting type (Owner list, then visible and openable for a Guest in a separate context); form validation at the title/duration fields (10, 20, 255; the form is `noValidate`, so the backend `fieldErrors` text shows); empty state «Предстоящих встреч нет»; Bookings in the Owner zone Asia/Almaty (the browser is Tbilisi, so a wrong zone fails) with guest name/email, ascending by start; a started meeting disappears after «Обновить» once `POST /__test__/clock` moved the clock. Setup Bookings go through the real backend API (`http://127.0.0.1:8080/api/bookings`), not the guest UI (guest.spec.ts covers that). The in-flight disabled state of «Обновить» is left to component tests (not deterministic against the real backend).
- Behind the corporate proxy browser download needs `HTTPS_PROXY` + `https_proxy` (both: `mise` blanks the upper-case one alone) and `NODE_USE_SYSTEM_CA=1` (verified; without it `SELF_SIGNED_CERT_IN_CHAIN`); alternative `NODE_EXTRA_CA_CERTS` (PEM path). Never `NODE_TLS_REJECT_UNAUTHORIZED=0`. Installed Edge on the dev machine refuses headless mode (admin policy), so `PW_CHANNEL=msedge` does not work there.

## Commits

- Conventional Commits (`feat`, `fix`, `docs`, `chore`, `ci`, `test`, `refactor`, `!` for breaking changes) with optional scopes `api`, `backend`, `frontend`, `e2e`.
- **Every implementation commit must reference its GitHub Issue** (the ticket from spec #16), in the message body or subject: `Closes #N` when the commit completes that ticket's acceptance criteria, otherwise `Refs #N`. One ticket per commit series; do not mix tickets in a commit.
- Never merge into `master` or push without the owner's explicit confirmation; never force push.

## Version constraints

- All dependency versions are pinned exactly (no `^`/`~`). Backend versions live in `backend/gradle/libs.versions.toml`.
- TypeScript must stay on 6.0.x: typescript-eslint 8.x supports `<6.1.0` only, although npm `latest` is 7.x.
- TypeSpec packages (`compiler`, `http`, `openapi3`) must share the same version. Emitter target is OpenAPI 3.0.0 (`api/tspconfig.yaml`).
- Version catalog keys: avoid names where one key is a prefix of another with a dash (e.g. `ktlint` and `ktlint-plugin`) since `libs.versions.ktlint` then becomes a group, not a value.
- `@hey-api/openapi-ts` is 0.x with frequent breaking changes: bump deliberately and re-check generated output.

## Environment notes (corporate network)

- Developer machine is behind an authenticated HTTP proxy with corporate TLS certs and an internal Nexus mirror. Never disable SSL verification. Keep corporate URLs and credentials out of the repo: committed files must reference only public sources (`mavenCentral()`, `registry.npmjs.org` in lock files, `services.gradle.org` in the wrapper). Local mirror/proxy/truststore settings belong in `~/.gradle` and `~/.npmrc` (see README).
- After `npm install`, rewrite any mirror host in `package-lock.json` `resolved` URLs back to `https://registry.npmjs.org/` before committing. Use `npm ci --ignore-scripts` for installs.
- Files use LF (`.gitattributes`, `.editorconfig`); ktlint enforces `.editorconfig`, so CRLF breaks `ktlintCheck`.
