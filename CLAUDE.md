# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Appointment-booking web app (Calendly-like), Hexlet learning project. Endpoints so far: `GET /api/health`, `GET /api/owner`, `GET /api/meeting-types`, `GET /api/meeting-types/{id}`, `POST /api/meeting-types`; no other business logic yet.

## Do not touch

- `.github/workflows/hexlet-check.yml` is auto-generated by Hexlet: never edit, delete or rename it (nor the repo). Own CI lives in `.github/workflows/ci.yml`.

## Architecture: contract-first pipeline

```
api/*.tsp (TypeSpec: main, owner, meeting-types, errors) --tsp compile--> api/openapi/openapi.yaml (OpenAPI 3.0.0, committed)
                                              |--> frontend/src/api/generated/ (hey-api SDK, gitignored)
backend/ (Ktor) implements the contract by hand (no server codegen)
```

- The API contract is the source of truth: change the `api/*.tsp` files, rebuild, then regenerate the SDK. CI fails (`git diff --exit-code -- api/openapi`) if the committed `openapi.yaml` is stale, so commit it together with `.tsp` changes.
- `frontend/src/api/generated/` must never be edited or committed; it is regenerated by `sdk:generate` and excluded from ESLint. Any frontend task needing the SDK depends on `sdk:generate` in `mise.toml`.
- Backend routes are not generated from OpenAPI, so keep `backend/src/main/kotlin/calendar/Application.kt` routes/DTOs manually in sync with the `.tsp`. All routes live under `/api`; Vite dev server proxies `/api` to `localhost:8080`, and the SDK is generated with a relative base URL (`baseUrl: false` in `frontend/openapi-ts.config.ts`).
- Backend config comes from env vars (`AppConfig.fromEnvironment`, passed into `Application.module(config)`): `OWNER_NAME`, `OWNER_BIO`, `OWNER_TIME_ZONE` (IANA id, validated at startup), with defaults. Unhandled exceptions become 500 `ApiError {code: INTERNAL_ERROR}` via StatusPages. Meeting types live in memory behind `MeetingTypeRepository` (`Application.module(config, meetingTypes)`; the default is seeded with 15 and 30 minute types, lost on restart); an unknown or malformed id gives 404 `MEETING_TYPE_NOT_FOUND`. Kotlin `allWarningsAsErrors` is on.
- Request validation lives in one module, `backend/src/main/kotlin/calendar/Validation.kt` (`Limits` constants, `validateMeetingTypeInput`, `trimmedLength`); add new rules there, never inline in routes. Text is trimmed, then measured in Unicode code points. Bodies are parsed strictly by hand (`Json.parseToJsonElement`): broken JSON gives 400 `MALFORMED_REQUEST`, unknown fields/wrong types/bounds give 400 `VALIDATION_ERROR` with `fieldErrors`. The TypeSpec `minLength`/`maxLength` count UTF-16 units in OpenAPI tools, so they only document the bounds; the backend is authoritative.
- Backend API tests check every response against the contract with one shared helper: call `response.assertMatchesContract()` (`backend/src/test/kotlin/calendar/ContractValidator.kt`, `openapi-request-validator-core`, test-only) on each `testApplication` response, including 404/500 `ApiError` ones; do not hand-write schema checks. For POSTs pass the request body (`assertMatchesContract(body)`) so the request is validated too, or `validateRequest = false` for requests that are invalid on purpose. The helper validates status, `Content-Type`, body schema and formats (`uuid`) and rejects undeclared fields, statuses and paths. `build.gradle.kts` passes `api/openapi/openapi.yaml` to tests as the `openapi.spec` system property and a task input, so tests re-run when the contract changes. Not caught: constraints that are not in the schema (e.g. a path `id` without `format: uuid`, IANA time zones, multiples of 15 minutes).
- Operation names in TypeSpec become SDK function names (`op getHealth` -> `getHealth()`). `@operationId` is not available without adding `@typespec/openapi`.

## Frontend pages

Routes via `react-router` (`BrowserRouter` in `main.tsx`): `/owner` (`OwnerPage`: permanent no-auth warning, meeting-type list, create form with field errors from `fieldErrors`; public, deliberately NOT linked from the home page), `/` (`HomePage`, meeting-type cards) and `/book/:meetingTypeId` (`BookingPage`, slot picker still a placeholder; the meeting type comes from `GET /api/meeting-types/{id}`, a 404 shows "Тип встречи не найден" with a link home). The owner block (`GET /api/owner`) and the cards (`GET /api/meeting-types`) are loaded via the generated SDK with loading/error/success states (`useApiResource`; tests stub fetch with `src/testApi.ts`). There is no static meeting-type data in the frontend. Never hand-write TS copies of API DTOs: import them from `./api/generated`. Domain terms: `GLOSSARY.md`; not-yet-implemented business rules: `docs/domain-rules.md`.

## Commands

Everything is driven by mise (Java `temurin-21`, Node `24`); CI runs the same command.

```
mise run check            # full pipeline: api format, SDK gen, frontend typecheck/lint/test/build, backend ktlint/test/assemble
mise run dev:backend      # Ktor on :8080
mise run dev:frontend     # Vite on :5173
mise tasks                # list all tasks
```

Single tests / direct tools (run inside the subproject):

```
cd backend  && ./gradlew test --tests "calendar.HealthTest"      # Windows: gradlew.bat
cd backend  && ./gradlew ktlintFormat                            # auto-fix ktlint
cd frontend && npx vitest run src/App.test.tsx -t "home page lists meeting types"
cd api      && npm run build                                     # regenerate openapi.yaml
cd frontend && npm run generate:sdk                              # needs api/openapi/openapi.yaml
```

mise Gradle tasks call `java -classpath gradle/wrapper/gradle-wrapper.jar org.gradle.wrapper.GradleWrapperMain` instead of `./gradlew` so they work in PowerShell, cmd and POSIX shells alike.

## Commits

- Conventional Commits (`feat`, `fix`, `docs`, `chore`, `ci`, `test`, `refactor`, `!` for breaking changes) with optional scopes `api`, `backend`, `frontend`, `e2e`.
- **Every implementation commit must reference its GitHub Issue** (the ticket from spec #16), in the message body or subject: `Closes #N` when the commit completes that ticket's acceptance criteria, otherwise `Refs #N`. One ticket per commit series; do not mix tickets in a commit.
- Never merge into `master` or push without the owner's explicit confirmation; never force push.

## Version constraints

- All dependency versions are pinned exactly (no `^`/`~`). Backend versions live in `backend/gradle/libs.versions.toml`.
- TypeScript must stay on 6.0.x: typescript-eslint 8.x supports `<6.1.0` only, although npm `latest` is 7.x.
- TypeSpec packages (`compiler`, `http`, `openapi3`) must share the same version. Emitter target is OpenAPI 3.0.0 (`api/tspconfig.yaml`).
- Version catalog keys: avoid names where one key is a prefix of another with a dash (e.g. `ktlint` and `ktlint-plugin`) since `libs.versions.ktlint` then becomes a group, not a value.
- `@hey-api/openapi-ts` is 0.x with frequent breaking changes: bump deliberately and re-check generated output.

## Environment notes (corporate network)

- Developer machine is behind an authenticated HTTP proxy with corporate TLS certs and an internal Nexus mirror. Never disable SSL verification. Keep corporate URLs and credentials out of the repo: committed files must reference only public sources (`mavenCentral()`, `registry.npmjs.org` in lock files, `services.gradle.org` in the wrapper). Local mirror/proxy/truststore settings belong in `~/.gradle` and `~/.npmrc` (see README).
- After `npm install`, rewrite any mirror host in `package-lock.json` `resolved` URLs back to `https://registry.npmjs.org/` before committing. Use `npm ci --ignore-scripts` for installs.
- Files use LF (`.gitattributes`, `.editorconfig`); ktlint enforces `.editorconfig`, so CRLF breaks `ktlintCheck`.
